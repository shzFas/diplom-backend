# Правила предметной области

Правила, которые нельзя вывести из кода и которые должны переживать любую смену
стека. Каждое помечено тем, где оно проверяется: в базе (нельзя обойти гонкой),
в доменном слое (чистая функция, покрытая тестами) или в сервисе.

---

## 1. Учебный календарь

| | Правило | Где проверяется |
|---|---|---|
| **D1** | Учебный год состоит максимум из 4 четвертей | `CHECK (ordinal BETWEEN 1 AND 4)` |
| **D2** | Четверти внутри года не пересекаются по датам | `EXCLUDE USING gist` на `terms` |
| **D3** | Дата урока лежит внутри своей четверти | триггер `lesson_date_within_term` |
| **D4** | Закрытая четверть (`closed_at IS NOT NULL`) не принимает новые и изменённые оценки | сервис |

**D4** намеренно не в базе: закрытие четверти должно быть обратимым решением
завуча, а не жёстким запретом. Откат оформляется как переоткрытие с записью
в аудит.

---

## 2. Оценивание

| | Правило | Где проверяется |
|---|---|---|
| **D5** | В четверти по одному предмету у класса не более одного СОЧ | частичный `UNIQUE INDEX` на `lessons` |
| **D6** | Одна оценка на ученика за урок | `UNIQUE (lesson_id, student_id)` |
| **D7** | Балл в пределах `0 .. lessons.max_score` | `CHECK` + триггер `grade_within_lesson_max` |
| **D8** | Оценку ставит только учитель, назначенный на этот класс и предмет | сервис (см. `permissions.md`) |
| **D9** | Ученику можно поставить оценку, только если он числился в классе на дату урока | сервис |

**D9** — прямое следствие временно́й модели. Проверяется запросом:

```sql
SELECT EXISTS (
    SELECT 1 FROM enrollments e
    JOIN teaching_assignments a ON a.class_id = e.class_id
    JOIN lessons l              ON l.assignment_id = a.id
    WHERE e.student_id = :studentId
      AND l.id         = :lessonId
      AND l.lesson_date BETWEEN e.from_date
                            AND COALESCE(e.to_date, 'infinity'::date)
);
```

## 3. Посещаемость

| | Правило | Где проверяется |
|---|---|---|
| **D10** | Посещаемость независима от оценки: возможны все четыре сочетания | модель данных |
| **D11** | Статусы: `PRESENT`, `EXCUSED`, `UNEXCUSED`, `LATE` | `ENUM attendance_status` |

Булев `markFalse` версии 2023 года не отличал болезнь от прогула. Школа
отчитывается именно этим различием, поэтому оно в типе, а не в комментарии.

## 4. Итоговая оценка за четверть

> **Не реализовывать по памяти.** Веса СОР и СОЧ и пороги перевода в
> пятибалльную шкалу задаются нормативным актом и со временем менялись.
> Перед написанием кода сверься с действующим приказом МОН РК и внеси
> найденные значения в конфигурацию, а не в код.

**Форма расчёта** (структура зафиксирована, числа — конфигурация):

```
sor_percent   = Σ(баллы СОР)  / Σ(max_score СОР)  × 100
soch_percent  = Σ(баллы СОЧ)  / Σ(max_score СОЧ)  × 100
total_percent = sor_percent × W_SOR + soch_percent × W_SOCH
final_score   = порог(total_percent)     -- в шкалу 1..5
```

| | Правило | Где проверяется |
|---|---|---|
| **D12** | Расчёт — чистая функция от списка оценок и версии формулы, без БД и без Spring | доменный слой |
| **D13** | Пока четверть открыта, итоговая не хранится, а считается при запросе | сервис |
| **D14** | При закрытии четверти результат замораживается в `term_grades` вместе с `formula_version` | сервис |
| **D15** | Изменение весов не пересчитывает замороженные четверти | `term_grades.formula_version` |

**D12** — то, ради чего затевалось разделение слоёв: эта функция переживёт
смену фреймворка, базы и языка, и она единственная требует настоящих
юнит-тестов на граничные случаи (нет ни одного СОР; СОЧ не проводился;
ученик переведён в середине четверти).

**Открытый вопрос для D12:** как считать ученика, переведённого в середине
четверти, — по оценкам обоих классов или только нового. Решение зависит от
методики; до выяснения расчёт ведётся по всем оценкам ученика за четверть
независимо от класса.

## 5. Аудит

| | Правило | Где проверяется |
|---|---|---|
| **D16** | Создание, изменение и удаление оценки пишется в `grade_audit` | сервис |
| **D17** | Запись аудита переживает удаление самой оценки | `grade_audit.grade_id` без FK |
| **D18** | Учитель не удаляется из системы, а деактивируется | `users.deactivated_at` |

**D18** — иначе `ON DELETE RESTRICT` на `grades.graded_by` заблокирует удаление,
либо, при `CASCADE`, унесёт с собой выставленные оценки.
