# Матрица прав

Отправная точка: **в версии 2023 года сервер не авторизовал никого.**
`checkAuth` проверял только подпись JWT публично известным секретом `secret123`,
не различал учителя и ученика, и не висел на большинстве эндпоинтов вовсе —
`GET /students`, `DELETE /student/:id`, весь CRUD предметов, планов и оценок
отвечали анонимному вызову.

Здесь описано целевое состояние. Каждая строка — приёмочный критерий фазы 02.

---

## Роли

| Роль | Кто это |
|---|---|
| `ADMIN` | Завуч: заводит пользователей, классы, предметы, назначения, четверти |
| `TEACHER` | Учитель: ведёт планирование и журнал в своих назначениях |
| `STUDENT` | Ученик: читает только собственную успеваемость |

Роль лежит в `users.role` и в claim `role` access-токена. Роли не наследуют
права друг друга: `ADMIN` — не надмножество `TEACHER`.

---

## Матрица

| Ресурс | ADMIN | TEACHER | STUDENT |
|---|---|---|---|
| `users` | CRUD | читает коллег и учеников своих классов | читает только себя |
| `classes` | CRUD | читает свои | читает свой текущий |
| `subjects` | CRUD | читает все | читает свои |
| `teaching_assignments` | CRUD | читает свои | — |
| `enrollments` | CRUD | читает состав своих классов | читает свои |
| `terms` · `academic_years` | CRUD | читает | читает |
| `lessons` | читает | **CRUD в своих назначениях** | читает уроки своего класса |
| `grades` | читает + аудит | **CRUD в своих назначениях** | читает только свои |
| `attendance` | читает | CRUD в своих назначениях | читает только свою |
| `term_grades` | читает, закрывает четверть | читает свои назначения | читает только свои |
| `grade_audit` | читает | читает по своим оценкам | — |
| `outbox` | — | — | — |

`ADMIN` намеренно **не** имеет права записи в `grades`: правка оценок —
исключительно учительское действие, и обход этого правила административной
ролью сделал бы аудит бессмысленным.

---

## Проверки владельца

Роли недостаточно: токен учителя не должен открывать чужой класс, токен
ученика — чужие оценки. Это те самые IDOR, которых в версии 2023 года не было
вообще. Три предиката покрывают все случаи:

```sql
-- P1. Учитель владеет уроком
a.teacher_id = :currentUserId
  FROM lessons l JOIN teaching_assignments a ON a.id = l.assignment_id

-- P2. Ученик владеет оценкой
g.student_id = :currentUserId

-- P3. Ученик видит урок, если числился в классе на дату этого урока
EXISTS (SELECT 1 FROM enrollments e
        WHERE e.student_id = :currentUserId
          AND e.class_id   = a.class_id
          AND l.lesson_date BETWEEN e.from_date
                                AND COALESCE(e.to_date, 'infinity'::date))
```

**P3** — не педантизм: переведённый ученик должен видеть сентябрьские уроки
старого класса и не должен видеть сентябрьские уроки нового. Проверка по
текущему `class_id` дала бы оба ответа неверно.

## Аутентификация

| | Решение |
|---|---|
| Access-токен | 15 минут, claims `sub`, `role`, `jti`. Не хранится на сервере |
| Refresh-токен | 30 дней, хеш в `refresh_tokens`, отзываемый |
| Logout | Отзыв конкретного refresh-токена |
| Смена пароля | Отзыв **всех** refresh-токенов пользователя |
| Секрет | `JWT_SECRET` из окружения. Приложение падает на старте, если переменной нет |
| Хеш пароля | Argon2id |
| Привязка Telegram | `telegram_chat_id` пишется только сервером после подтверждения владения чатом. Клиент не передаёт его сам |

---

## Публичные эндпоинты

Ровно четыре. Всё остальное требует валидного access-токена:

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `GET  /api/v1/health`
- `GET  /api/v1/docs`

Регистрации самозаписью нет: учеников и учителей заводит `ADMIN`.
В версии 2023 года `POST /auth/register` был открыт, что позволяло любому
создать себе учительский аккаунт.

## Приёмочные тесты фазы 02

Реализованными эти правила считаются, когда зелены следующие интеграционные тесты:

- [x] ученик A получает 403 на оценки ученика B
- [x] учитель получает 403 на журнал чужого класса
- [x] токен ученика получает 403 на `POST /grades`
- [x] `ADMIN` получает 403 на `POST /grades`
- [x] переведённый ученик видит сентябрьские уроки старого класса и не видит новые
- [x] запрос без токена получает 401 на каждом непубличном эндпоинте
- [x] `passwordHash` не встречается ни в одном ответе API
- [x] после смены пароля прежний refresh-токен получает 401

**Все восемь закрыты.** Проверки живут в `SecurityBoundaryIntegrationTest`,
`AuthFlowIntegrationTest`, `LessonIntegrationTest` и `GradeIntegrationTest`.

Четыре критерия про оценки закрыты вместе с модулем `grades`. Права на
запись оценок принадлежат только `TEACHER`, и только в своих назначениях:
`ADMIN` получает `ROLE_FORBIDDEN`, чужой учитель — `NOT_OWNER`, ученик —
`ROLE_FORBIDDEN` на запись и `NOT_OWNER` на чужие оценки. Журнал урока
ученику не показывается вовсе.

Предикат P3 применён к урокам: `LessonRepository.findVisible` сравнивает
дату урока с интервалом зачисления, а не с текущим классом ученика.
Переведённый ученик видит сентябрьский урок прежнего класса и февральский
урок нового, и не видит двух остальных — проверено и тестом, и запросом
к работающему сервису.

Помимо списка выше проверено: истёкший токен отличается от отсутствующего
и от подписанного чужим секретом; деактивированный пользователь не входит;
refresh-токен ротируется и повторно не принимается; неизвестный email
и неверный пароль неразличимы в ответе.
